# 登录拼图验证（滑块）与登录限流

> 覆盖：滑块拼图的实现与分层、**它为什么是装饰品（含实测攻击数据）**、挑战生命周期、登录限流硬化（每 IP + 全局指数退避）、登录页拖拽控件、设置页开关、已知局限与观察哨。会话与信任判定见 `auth-mechanics.md`。
>
> **定位**：这是**应网友要求加的、没什么用的防人机验证**——设置页的说明文案就是这么写的。它是彩蛋，不是安全边界。真正让爆破不划算的是本文最后一节的限流。

## 一句话结论

**滑块挡不住脚本。** 拼图的答案（缺口在哪）**必须画在图上**，因为人要看着它拖；画在图上的东西，几十行代码就能读出来。这是滑块这个形态的固有性质，不是实现问题。

实测（2026-09-24，本机）：把滑块按常规做法实现成三种变体，各 100 次随机位置，用约 30 行脚本攻击（容差 ±3px）：

| 滑块变体 | 亮度攻击 | 边缘攻击 | 方差攻击 | 人眼可解？ |
|---|---|---|---|---|
| 缺口涂暗（本插件采用） | **100%** | **100%** | — | 能 |
| 缺口只描边 | 0% | **100%** | **100%** | 能 |
| 缺口撒噪点（"防脚本"做法） | 1% | 11% | **97%** | **不能** |

第三行是关键：撒噪点确实挡住了亮度和边缘检测，但**人也看不见该往哪拖了**；而噪点区自身成了更强的信号（局部方差：背景中位数 144，缺口内 238–357），15 行游程检测就能定位到 97%。**要么脚本能读，要么人也读不了**——这个二选一没有出路。

同类机制也一样：之前实现过的 4 位数字图片题，用模板匹配（利用七段字体的固定几何）攻击，参数调优后拿到**数字级 99.2%、整图 96.7%**；工作量证明（PoW）虽然答案不在图里，但浏览器能算的脚本都能算（而且原生哈希快 2–10 倍、GPU 快约 4 个数量级），实测难度 16 时对攻击者的成本约为每次 0.05 秒。两者都已被移除，只留滑块。

**要真正提高门槛，只有三条路**（都不在"验证码"这个形态里）：限制尝试次数（限流，已有）、要求脚本没有的秘密（TOTP 两步验证）、或者干脆别暴露端口（VPN / 内网）。

## 实现

### 分层（改代码前先读）

`src/auth.ts` 只 import `src/slider/index.ts`：

```
auth.ts ──▶ slider/index.ts ──┬──▶ slider/challenge.ts   领域：几何、容差、答案生成、路径
                              └──▶ slider/render.ts      表现：程序化背景 + 缺口 + 拼图块 → SVG
            两者共用 ──▶ challenge-store.ts              一次性挑战表（TTL / 上限 / 取即删）
```

- `index.ts` 只收 `clientKey: string`，不收 `IncomingMessage`：哪个地址算"客户端"的决定留在 `auth.ts`，和限流器用的是同一个判断（`clientIp`，即 socket 对端地址，刻意不信任 `X-Forwarded-For`）。
- `render.ts` 的纹理由 seed 决定，纯函数、可复现；背景与拼图块**由同一次纹理生成**，所以拼图块上带着"本该在缺口里"的像素——这正是"拖对了就对上"的原理。

### 出题与判分

1. `GET /api/auth/challenge`（**匿名**，`/api/auth/` 前缀天然豁免于路由守卫）→ 关时 `{ enabled: false }`；开时返回 `id`、`background`、`piece`（都是内联 `data:image/svg+xml;base64,…`）以及**几何参数**（`width`/`height`/`pieceWidth`/`pieceHeight`/`startX`/`startY`/`tolerance`，其中 `pieceWidth`×`pieceHeight` **随剪影变化**：横凸 58×44、竖凸 44×58、无凸 44×44）。`theme=dark` 是表现提示。
2. 记录写入内存表：`{ answer: {x, y, tab} }`（位置**二维** + 剪影——判分只用 `x,y`，**剪影不走 wire**，玩家从图上读）+ 签发时的 `clientKey` + `expiresAt`（5 分钟）。
3. 登录页把拼图块从起始角（左下角，`startX`/`startY`——**刻意不在缺口那一行**，对齐要两轴都做功）**自由拖动**（横纵双向，不是只能水平滑）到缺口处，提交时带 `challengeId` + `challengeAnswer`（= `"x,y"`，拼图块外接框左上角的坐标对，各自取整——**外接框**锚点对任何剪影都成立，凸块朝左/上时只是把主体往里推 14 单位）。
4. `POST /api/auth/login` 校验顺序：**锁定检查 → 字段存在 → 拼图 → 密码比对**。拼图判定为**两轴**都在 `TOLERANCE`（±4 画布单位）内。

**无论对错都消费**（取即删），所以一张图只买一次尝试；失败计入限流预算，并返回 `400 { error, challengeExpired: true }`。

### 假缺口（decoy）

每张图在真缺口之外画**一个假缺口**：同样的压暗剪影、同样的只填色不描边，但**形状不同**——真缺口的剪影每张图**随机**（五选一：凸块朝右/左/上/下，或没有凸块的圆角方块，拼图块永远同形），假缺口永远取**另外四种之一**。辨认方式就是看形状：拼图块只塞得进和它形状相同的那个洞（提示文案"对准图中和它形状相同的缺口"就是在说这件事）。

- **生成**（`challenge.ts` 的 `pickDecoy`）：形状随机取自 `ALL_TABS` 里**除真缺口之外**的四种剪影；位置随机，但硬性避开两处——真缺口（按其剪影的完整外接框算）与拼图块起始角（按本题剪影的尺寸算），各留 `DECOY_GAP`（12 单位）净空（挨着真洞会干扰判断，盖在起始块下面就看不见）。重试 64 次后用一个对所有答案都合法的兜底落点（兜底形状同样取"非真缺口"的首个候选）。
- **判分上永远不放水**：假缺口（按外接框角点，即"把拼图块拖到假洞上"的提交位置）永远落在接受窗口外（单测 200 次随机 + 五种剪影的兜底用例钉死），拖到假洞提交只会吃一次「拼图没有对上」+ 一张新图。
- **渲染管线同源**：假缺口与真缺口共用 `piecePath`（同一个路径生成器，凸块边不同）与同一个 `slotFill`，"只填色不描边"的规则自动对两者一致生效。
- **它挡不住脚本**：剪影匹配和人眼辨认一样容易，脚本找到"和拼图块同形"的洞就完了——这不改变本文的结论，它就是图更好玩。

**为什么验证必须在密码之前**：若先比密码，攻击者就能用伪造的 `challengeId` 无限探测密码——密码错时根本不碰拼图，验证形同不存在。代价是**任何**被拒的登录都已消耗拼图，所以登录页必须在**每一次失败后**重新取图，而不只是收到 `challengeExpired` 时（这个 bug 是浏览器 E2E 抓到的：输错密码后重试会先吃一次"拼图没有对上"）。

**盲猜的实际强度**：±4 的窗口在两轴上各覆盖 9 个位置，而可拖范围约 242 × 79 ≈ 19000 个位置（x 为最宽拼图块的拖动范围，y 为缺口行的取值范围），**两轴都要蒙对**，即单次盲猜命中率约 **0.4%**（`slider.spec.ts` 把这个乘积钉成断言）。挡不住盲猜的从来不是拼图难度，而是"一次性 + 限流"。

**为什么用内存表而不是签名令牌**：关键性质是**一次性**。无状态签名令牌在 TTL 内可反复使用；取即删的记录不能。也没有可伪造面：id 是 128 位 CSPRNG 输出，从不出现在图片里。代价是重启丢挑战（重试一次）与单进程限制（dsh web 本来就是单进程）。

### 渲染上的坑与约定（都已修/定，别再犯）

1. **拼图块必须整体裁剪**，不能只裁纹理：只裁纹理会让底色铺满整个 viewBox，于是"拼图块"是一个不透明矩形、轮廓浮在里面（看渲染图才发现）。`tests/slider.spec.ts` 用"背景与拼图块的纹理图元逐条相同"钉住同源，浏览器侧另有像素级校验。
2. **暗色底不能太暗**：缺口是"压暗的剪影"，底色接近纯黑时缺口和待拖的拼图块都看不见（看暗色渲染图才发现）。暗色 palette 刻意用中间调。
3. **缺口只填色、不描边**：描边的缺口读起来像"画了个框"而不是"挖了个洞"，而且描边本身就是机器可读的边缘信号（上表"只描边"变体被边缘攻击 100% 命中）。拼图块自身保留一圈白描边（`pieceStroke`，裁剪后只露内半圈）——那是"可拾取"的暗示，不是答案的一部分，别把两者混为一谈。

**像素级对齐校验**（一次性脚本，`/tmp`，依赖 playwright；改渲染后五种剪影 × 明暗都跑）：第一重是**纯几何对照**——同一背景"删掉洞的路径"当对照图，拼图块落在缺口锚点上后与对照逐点比，剪影不匹配会整片差几十，实测五种剪影**最大每通道 ≤2、768 点 0 个超阈**（纯 SVG 光栅路径舍入）。第二重按 `slot = α·base + (1-α)·texture` 把缺口像素反解回原纹理再比（模拟人眼看到的对齐），实测最大偏差 ≤3、超阈 ≤3/768——叠加遮罩的双重舍入经 1/(1-α) 放大后的量级，不是错位。同时确认拼图块轮廓外**透明**（真裁剪）。另有**缺口无描边**校验（真缺口与假缺口都查）：把带洞的背景与"删掉这个洞的路径"的对照图逐像素相减——半透明压暗只能让像素**变暗**，所以凡是变亮的像素都必是描边；实测 5 剪影 × 明暗共 10 例、每例两洞，**0 个变亮像素**。（注意别用"轮廓上单点比两侧亮"的亮脊采样法：程序化纹理自带亮条纹，会误报——踩过一次。）这几条只能靠浏览器验，字符串级测试抓不到。

## 设置页开关（默认关闭）

- 配置项 `slideVerification`（布尔）存在凭据文件里，`getSlideVerification()` / `setSlideVerification()`。
- **未注册时拒绝开启**：`hasCredentials()` 判的是**文件是否存在**，为了存一个开关而创建该文件会让注册表单永久关闭——第一个管理员再也建不出来。设置页在未注册时提示"需先设置管理员账号才能开启"，点了会引导去 `/login`。
- 端点 `GET|POST /api/auth/challenge-policy`（需认证），字段 `slideVerification`。前端在设置面板「认证」→**人机验证**卡片里，滑动开关形态与「登录要求」一致；读不到状态时渲染为**未知态**（禁用 + 半透明 + "正在读取设置…"），绝不拿默认值当 OFF。
- 卡片文案只有那句**"应网友要求加上了没什么用的防人机验证，有兴趣可以开启试试 XD"**（不附带其他说明小字；只有未注册/读取中才显示各自的提示行）。**别把它改成安全承诺**。

## 登录页拖拽控件（`src/login-page.ts`）

- 加载即 `GET /api/auth/challenge` 探测开关。`sliderEnabled` **初值 false**，只有服务端明确回答才为真；取不到时字段保持隐藏、提交不带挑战字段——一个从没开过开关的部署不能被一次无关的 fetch 失败锁住。
- 字段只在**登录**模式显示（`sliderVisible()` = 开关为真且 `mode === 'login'`）。两个读（status / challenge）是竞态的，各自都调一次可见性刷新。
- **几何全部来自接口**，页面不硬编码任何画布尺寸。
- 拖拽用 **pointer events**（鼠标/触屏同一套），配 `setPointerCapture`（快速拖动时不掉块）与 `touch-action: none`（否则触屏拖动会变成滚页面）。
- **自由二维拖动**：`pointermove` 同时换算 x/y 两个方向的位移（同一个缩放比，因为舞台就是背景图的宽高比），再各自 clamp 回可拖范围——不是只能沿水平轨道滑。起始角 `startX`/`startY` 由服务端给出，**刻意不在缺口那一行**，所以对齐必须两轴都做功。
- **定位用百分比**（`left/top/width/height` 都是相对舞台的百分比），所以卡片在手机上变窄时控件自动缩放；只有"拖动位移换算成画布单位"需要读一次 `getBoundingClientRect()` 求缩放比。
- 未拖动就提交会被前端拦下（"请先拖动拼图块"）——起始位置永远不可能是缺口，这只是省一次往返。
- **每次失败都重取**（见上），并把拼图块**复位到起始角**。
- **拼图输错即清空密码框**（收到 `challengeExpired` 时）：验证在密码之前，所以"拼图没对上"的那一次根本没有比对过密码，此时留着已输入的密码只会让人凭肌肉记忆对着新图再交一次。密码错（非拼图错）不清空——那不是拼图的问题。

## 登录限流（这才是真正起作用的部分）

两层，形状不同，各管一类攻击：

**① 每 IP 锁定**：10 分钟窗口内 5 次失败 → 锁 30 秒。挡单源暴力。

**② 全局指数退避**：所有客户端的失败总数累计，超过 20 次免费额度后按台阶翻倍，封顶 5 分钟：

| 累计失败 | 20–29 | 30–39 | 40–49 | 50–59 | 60–69 | 70–79 | ≥80 |
|---|---|---|---|---|---|---|---|
| 惩罚 | 5 s | 10 s | 20 s | 40 s | 80 s | 160 s | **300 s（封顶）** |

**为什么需要它**：每 IP 限流对**分布式**撞库无效——一千个地址各试几次，没有一个会触发。全局计数才是让聚合流量付出代价的东西。窗口 1 小时，超时后清零。

**把攻击者压到多少**：前 20 次免费；之后 60 次尝试要走完 5s→160s 的台阶（约 53 分钟）；此后每 5 分钟才准试一次。**合计约每天 350 次密码猜测**——对比一下，滑块只贡献"每次多几十行代码"，PoW 在这个量级下约等于零成本。**所以真正防爆破的是限流，不是验证码。**

**可用性代价与对策**（任何全局限流都有这个代价）：

- **封顶 5 分钟**：攻击者最多能把管理员挡 5 分钟，不能永久锁死。
- **真回环豁免**：`isTrustedOrigin(req)` 为真（对端地址与 `Host` 双回环，且「本机登录校验」关着）时不受全局惩罚——这类调用者本来就不需要登录，惩罚它保护不了任何东西，却给了攻击者一个把管理员锁在自己机器外面的开关。开了「本机登录校验」后回环不再豁免。
- **成功登录不重置全局计数**：一次成功只说明"有人知道密码"，不说明聚合压力结束了；计数器按窗口自然衰减。因为惩罚有上限，这不会把任何人困住。
- **`Retry-After` 头**：429 响应带上剩余秒数，这是脚本客户端唯一会读的标准信号。

## 已知局限

- **挡不住任何认真写的脚本**：见上表，答案就在图里。
- **反向代理后 IP 绑定退化**：`clientIp` 是 socket 对端地址，代理后面所有客户端会塌缩成代理地址。与限流器共享这一局限，不额外恶化。
- **签发端点不设限流**：它是匿名的（登录页在持有会话前就要调）。挑战表有上限（`MAX_CHALLENGES` = 2048，超限驱逐最旧）兜住内存；**刻意不并入登录限流**——那等于给攻击者一个无需凭据就能把管理员锁在门外的开关。
- **全局限流是可用性攻击面**：靠封顶 + 回环豁免 + `Retry-After` 把影响限制在 5 分钟内。
- **进程内状态**：重启丢挑战；多进程部署（当前不存在）需要外部存储。

## 测试要点（`tests/`）

- `tests/challenge-store.spec.ts`：取即删、TTL 剪枝、上限驱逐、实例隔离、`take` 不检查过期（过期是调用方的决定）。
- `tests/slider.spec.ts`：**按层测**——领域（几何自洽、起始角避开缺口行且差值超容差、取端边界（含形状）、**五种剪影都会被抽到、签发几何随剪影变化**、容差边界（两轴，含"一轴对一轴错"必须拒）、`formatDrop`/`parseDrop` 往返、`parseDrop` 只接受控件可能产生的值、路径闭合且带弧、凸块可画在任意边；假缺口：形状≠真缺口、避让净空且不越界（真缺口外接框按剪影算）、锚点永不进接受窗口、**六十四连败后的兜底落点同样守规**）、表现（两份 SVG 自包含、**拼图块 viewBox 按剪影取自身外接框**、缺口画在答案处**且无描边**（五种剪影都查）、**两份文档纹理图元逐条相同**、假缺口被画进背景且不在真缺口上、seed 决定一切、主题取色）、编排（签发字段齐全、命中/未命中、取即删、空/畸形/换地址/过期/未知 id、不同挑战不复用图片、以及一条把"两轴盲猜命中率 ≈0.4%（<1%）"写成断言的文档化测试）。
- `tests/auth.spec.ts`：端点级（开关默认关、未注册拒绝开启且不落文件、策略读写与鉴权、`GET /api/auth/challenge` 的匿名/几何/主题/405、登录侧的无挑战/命中/未命中/换地址/重放/计入锁定/回环同样受限/关掉时不影响登录）+ **限流**（每 IP 锁定、全局退避的纯函数台阶与封顶、20 个不同地址打满额度后第 21 个被 429 且带 `Retry-After`、洪泛期间真回环仍可登录、开了本机登录校验后回环不再豁免）。`beforeEach` 调 `authInternals.resetLoginFailures()` 清空全局状态——否则一个测试的失败会泄漏给同文件后面所有测试。

## 观察哨

- **别把文案改成安全承诺**：这个功能的说明就是"没什么用"，文档、README、设置页三处保持一致。
- 改 `render.ts` 的调色板或裁剪 → 重跑 `tests/slider.spec.ts` 的"纹理同源"断言与 `/tmp/verify-alignment.mjs` 的像素校验（另跑 `/tmp/verify-noborder.mjs` 验缺口无描边）；**只跑单测不足以发现渲染错位**（本次两个渲染 bug 都是看渲染图/像素校验才发现的）。
- 改暗色 palette 时保持中间调：底色太暗会让缺口和待拖块都看不见。
- **改登录页的提交/失败分支时，务必保留"任何失败都重取挑战"**——去掉它会让输错密码后的重试必然失败一次（E2E 抓过一次）。
- 改 `TOLERANCE`、`MIN_ANSWER_X`、`MAX_ANSWER_X`、`MIN_ANSWER_Y`、`MAX_ANSWER_Y`、`START_X`/`START_Y` 或 `PIECE_*` → `slider.spec.ts` 的几何自洽与盲猜命中率断言会跟着变；确认是有意为之。**起始角必须落在缺口行之外**（`START_Y - MAX_ANSWER_Y > TOLERANCE`，现值 90 − 84 = 6 > 4），否则"两轴都做功"没了；`MAX_ANSWER_Y` 要为最高的剪影（竖凸 58 高）留出画布边距，`START_Y` 要让竖凸拼图块在起始角放得下。
- 改 `pickDecoy` 的避让规则（`DECOY_GAP`/兜底落点）→ 保持三条不变式：假缺口剪影**永远 ≠ 真缺口剪影**（`decoyTabs`，五种剪影轮换后靠这条辨认）、假缺口不挨真缺口（真缺口的外接框按其剪影算，竖凸/横凸尺寸不同）、不盖起始块（按本题剪影尺寸算），且锚点永不进接受窗口。**真缺口的剪影从 `ALL_TABS` 五种里每张随机**（右/左/上/下凸块、或无凸方块）——这是"辨认靠形状"的前提：任何一张图上假缺口都是另一种形状，兜底落点取"非真缺口"的首个候选，不许退化成同形。
- 上游若给 `webServer.register` 之外再加一层路由包装、或改了 `/api/auth/` 匿名前缀的判定（`auth.ts` 的 `isPublicRoute`）→ `GET /api/auth/challenge` 会需要会话，登录页直接失效（表现为拼图永远加载不出来）。
- 若将来要支持多进程/集群部署 → 内存表必须换外部存储，或退化成"签名 + 已用 nonce 集合"。
